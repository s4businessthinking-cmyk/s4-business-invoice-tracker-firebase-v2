So this is a new feature to build, using the field names already expected by the existing dead code: plate, make, model, vin, engine, customer.

TASK B — Product Catalog + Service Catalog (two separate master lists, new feature — DETAILED MODE ONLY, see scope note above)

CONTEXT: the invoice #invDetailedBlock item-entry mode currently requires manually typing every line item's Item/Product name, Code, Price, and VAT% from scratch on every single invoice — there is no saved catalog to pick from. Owner has decided: build TWO separate master lists (not one combined list), because spare-parts shops and workshops think about these differently — a Product has a part number and a Service does not. This entire task applies only within #invDetailedBlock — #invSimpleBlock (Total Amount mode) has no item rows and must not be touched.

Build two new Firestore collections, "productCatalog" and "serviceCatalog", each with their own modal, list page, and firestore.rules entry, following the exact same pattern as customers/saveCustomer() and Task A's Vehicle module:

1. firestore.rules: add
   match /productCatalog/{id} { allow read, create, update, delete: if isActiveMember(); }
   match /serviceCatalog/{id} { allow read, create, update, delete: if isActiveMember(); }

2. Product Catalog:
   - New modal (id="productModal") with fields: NAME (required), PART NUMBER / CODE, DEFAULT PRICE, DEFAULT VAT % (default to shop's standard VAT rate, same default the invoice line items already use), CATEGORY (optional, free text).
   - New sidebar nav entry + list page "Product Catalog" (reuse .table-wrap/.table pattern) with columns Name, Code, Price, VAT%, Category, and Edit/Delete actions.
   - saveProduct() in app.js: validate name is non-empty, addDoc/updateDoc to col("productCatalog"), same pattern as saveCustomer()/saveVehicle(). Before saving a NEW product, warn (confirm(), not hard block) if the same Part Number already exists.
   - listen("productCatalog", rows => { products = rows; renderProducts(); refreshSelects(); }) — new `let products = []` module-level array.

3. Service Catalog:
   - New modal (id="serviceModal") with fields: DESCRIPTION (required), DEFAULT LABOUR PRICE, DEFAULT VAT %, CATEGORY (optional, free text). No part-number field.
   - New sidebar nav entry + list page "Service Catalog", same table pattern, columns Description, Price, VAT%, Category, Edit/Delete.
   - saveService() in app.js: same validate/addDoc/updateDoc pattern. Warn (non-blocking confirm()) if a service with the same Description already exists.
   - listen("serviceCatalog", rows => { services = rows; renderServices(); refreshSelects(); }) — new `let services = []` array.

4. Wire both catalogs into the item entry row INSIDE #invDetailedBlock ONLY (the #invItemRows / .inv-entry-row structure):
   - As the user types in the Item/Product entry field, show a combined autocomplete/dropdown of matches from BOTH products and services, each result labeled "[Product]" or "[Service]" (e.g. "Brake Pad Set — PN-4521 [Product]" vs "Tire Change [Service]").
   - Selecting a match auto-fills Code (from part number, blank for services), Unit Price (from default price), VAT % (from default VAT) into the current entry row — Qty stays editable (default 1), and every auto-filled field remains fully editable afterward (the user can override price/VAT per-invoice; auto-fill is a convenience default, not a lock — do not add readonly to invEntryPrice or invEntryVat).
   - Typing something matching neither catalog must still work exactly as today — pure free text, no forced selection. Do NOT change the invoice line-item data structure (still just qty/price/disc/vat/name/code as normalizeInvLineItem() already expects).
   - Add a small "Save as new [Product/Service]" affordance next to the entry row: if the typed text doesn't match an existing catalog entry, offer a one-click way to save it into productCatalog or serviceCatalog (ask which of the two) for future reuse, without blocking the current invoice line from being added either way.
   - Confirm #invSimpleBlock is completely untouched by this — no catalog UI, no autocomplete, nothing added there.
