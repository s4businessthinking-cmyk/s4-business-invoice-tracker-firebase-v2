TASK 2 — Fix inv.paid / inv.credited drift + receipt-discount-not-linked bug (frontend/app.js)
Invoice balance is tracked two ways: (a) denormalized inv.paid/inv.credited updated per event, (b) ledgerLines() recomputed independently from receipts/creditNotes/debitNotes/discounts/cheques. These can drift.
Specific known bug: in saveReceipt(), when rvDisc > 0, a "discounts" record is created (customer-level ledger credit) but never added to inv.credited on the allocated invoice(s), so that invoice's balance/status never reflects the discount even though the ledger does.
Fix:
(a) In saveReceipt(), if allocs is non-empty AND discount > 0, distribute the discount proportionally across allocated invoices by each invoice's share of allocated amount, and add each invoice's share to that invoice's `credited` field in the same updateDoc call that already updates `paid` for that invoice. Round to 2 decimals, put rounding remainder on the last invoice in the list. If allocs is empty when a discount is given, leave current behavior (customer-level-only credit) and add a comment explaining why.
(b) Add an owner-only admin utility `recalculateInvoiceBalances()` in app.js that, for every invoice, recomputes correct `paid` (from receipt allocations + cleared cheques) and `credited` (from credit note allocations + proportional receipt discounts per the same logic as (a)) from the actual source records, and writes corrected values via updateDoc only where they differ from stored values. Returns { checked, fixed, details[] } shown in a toast/modal. Wire to a "Recalculate Balances" button in Settings, visible only to the owner role (use the existing role-check pattern already used elsewhere in the app).

TASK 7 — Fix reports.js money-calculation bugs (frontend/reports.js + app.js caller)
1. Draft invoices leaking into reports: at both call sites of buildReportBundle(invoices, ...) and invoicesToCsv(bundle.periodInvoices, ...) in app.js, filter Drafts first: pass invoices.filter(i => i.status !== "Draft").
2. statusOf()/sumInvoices()/dueAgingReport() in reports.js compute due as total-paid, ignoring `credited`. Change to Math.max(0, total - paid - credited) everywhere due/status is computed in reports.js, matching invBalance() in app.js.
3. Collections report always empty because inv.paidDate is never set anywhere. Fix: whenever an invoice's computed balance reaches 0 as a result of a receipt allocation, cheque clear, or credit note allocation, set paidDate: today() on that invoice in the same updateDoc call — in saveReceipt() (applyNow branch), applyReceiptToInvoices(), saveAllocation(), and saveCn() (allocation branch). If a reversal (bounced cheque, reverseReceiptFromInvoices) drops the invoice back to unpaid, clear paidDate back to "" there too. Also backfill paidDate on existing fully-paid invoices inside recalculateInvoiceBalances() (Task 2b).
4. CSV export "Car" column always blank: change inv.car to inv.vehicle in invoicesToCsv() row-building.
Verify after: an invoice paid via receipt+credit-note mix shows "Paid" in the Monthly Report's By Status table, contributes 0 to Outstanding Dues, has a non-empty Paid Date, and Draft invoices never appear in any report or CSV.
